# Execution Modes

仅在路由疑难或范围变化时读取。Operating Partner 始终启用，DIRECT/LIGHT/FULL 是同一资本配置轴；STOP_LOSS 是中断状态。

1. 先保留用户明确的审查范围、授权和不可省的质量要求。明确独立/ChatGPT 审查默认 FULL；明确仅本地独立审查按其范围执行。
2. 判断失败影响、未知、可逆性与返工代价，再看范围/价值。核心 schema、安全边界、数据损坏、架构影响通常 FULL；代码短不表示风险低。
3. 小而确定、低影响、高可逆用 DIRECT。共享布局/组件跨多个使用位置、需核对一致性时至少 LIGHT：跨位置回归面和共享约束决定投入，不按文件数量升级；纯文案批量替换仍可 DIRECT。中等有界、局部验证充分用 LIGHT。有重大影响或昂贵失败用 FULL。
4. 范围/证据改变时重分配并记一句原因。工具不支持 FULL 时按 capabilities.md 保留缺口，不为拿 PASS 改路由。

| 对照情境 | 选择与原因 |
|---|---|
| 无行为影响的按钮文案 | DIRECT；实查目标文字与未改行为 |
| 局部间距/样式 | DIRECT 或 LIGHT，取决于状态/响应式回归风险 |
| 多视图共用筛选布局 | 至少 LIGHT；须验证跨视图共享约束与响应式一致性，不因数量自动 FULL |
| 单行权限、核心 schema、不可逆迁移 | FULL；数据/安全风险支配规模 |
| 简单修改但明确要完整 ChatGPT 审查 | 保留明确审查范围；不是可选浪费 |
| 高价值业务中的无行为文案 | DIRECT；业务价值不代替实际改动风险 |

LIGHT 保留独立内部审查；DIRECT 没有大型计划、独立 Reviewer 或单独资本文件。普通“检查”仍需实查，不能借 DIRECT 省略；仅解释 findings 不代表获准改产品或外发材料。自然触发取决于 host，显式调用是后备；不为身份常开强制所有任务使用本 Skill。
