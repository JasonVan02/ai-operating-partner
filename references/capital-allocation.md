# Capital Allocation

LIGHT/FULL 在预算或验证保留存在实质权衡时读取；默认使用入口摘要，模式边界见 execution-modes.md。沿用同一个 Contract，不建第二份互相竞争的计划。

## 轻量 profile 与 reserve

按 [task capital profile](../templates/task-capital-profile.md) 记结果、价值/风险、关键未知、可逆性、返工代价、模式与下一有价值检验。LIGHT 通常几句；FULL 按风险展开。不为可从项目得知的字段打断用户。未给出的真实预算写 unknown，不虚构 token、工时或美元限制。

先保留必需验证、所需独立审查、合理修复与交付的能力，再投入可选探索和美化。Capital Reserve 是优先次序，不是固定百分比；预算不足先停可选项并保留未验证清单。明确预算或能力仍不足以满足 AC 时，做已授权独立工作，提出具体范围/资源选择，不能将未达标结果判 PASS。

## Marginal Intelligence Value

在计划/实施/评审边界，以及准备追加一次低产出动作时，问：“它会改变哪个 decision、risk、architecture 或未通过的 quality gate？”答案为空就结束该活动。这是隐含工作判断，不要求每次工具调用输出一段分析。

| 活动 | 继续所需的具体价值 | 停止 / 替代 |
|---|---|---|
| Search | 未解决问题、相冲证据、时效失效、必需源缺失 | 证据足够即停止；不为凑来源数再搜 |
| Reasoning | 尚未区分方案、未处理风险、新事实 | 结论稳定后实施或交付，不反复换措辞 |
| Tool / Codex / API / subagent | 必需操作、可回答问题、可独立降低的不确定性 | 已有结果可复用则复用；独立读取批量做，依赖动作顺序做 |
| Generation | 缺失产物或结构性失败的证据 | 局部缺陷局部改；整份重生成须说明局部修复为何不足 |
| Tests | 合同必需、风险变更或回归面 | 必要昂贵测试不可省；通过后无变化/疑点不重复 |
| Review | 路线要求的独立检查、实际变更、冲突或材料缺口 | 不因已有好评省必需外审；不为放心无限再审 |
| Rework | 明确原因、可证伪的修复与有界验证 | 同根因停滞按 stop-loss.md；不重写正确区域 |

达到 Gate 后停止可选优化。新关键缺陷应重开相关 AC，生成新快照并验证；“已经到过 Gate”不是永久豁免。
